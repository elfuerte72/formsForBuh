# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Service for the client "Выборг" (Russian bookkeeping). Serves a custom HTML upload form at `/` with two tabs:

1. **«Загрузка УПД»** — bookkeeper picks a foreman (Юра / Гриша / Боря) and uploads a UPD file (PDF or image). Backend rasterises PDFs to PNG, calls Claude Vision (tool-use) to extract five fields (`organization`, `counterparty`, `date`, `amount`, `upd_number`), optionally archives the **original** scan to Google Drive (feature-flagged) and writes its `webViewLink` into the «Файл» column (M), appends a row to a configured Google Sheet, and returns the result synchronously so the page can show a success / warning / error banner.
2. **«Сводка»** — bookkeeper uploads the weekly 1С export (`Реестр документов "Поступление (акт, накладная, УПД)"`, `.xls` / `.xlsx` / `.csv`). Backend parses the register, reads the foreman green-side rows out of the same Google Sheet, and **annotates the sheet in place — never clears or reorders**: it patches the yellow 1С block (A:D) + Status cell (L) next to each matching green row, appends still-missing 1С records as `NO` rows below, and deletes a stale yellow-only `NO` placeholder once a later upload matches it. Side-by-side: yellow block (1С) left, green block (foreman upload) right, status (`OK` / `СУММА?` / `NO` / `ЛИШНЕЕ`), file link far right. **History + manual statuses survive**: auto-statuses carry the `·авто` suffix and are refreshed every run; a status without the suffix is treated as manual and never overwritten. The frontend shows four numbers — Совпало / Не хватает / Лишние / Сумма ≠ — and points the bookkeeper at the spreadsheet. The «Сводка» tab also shows a hint when there are foreman uploads that arrived after the last reconciliation (green rows with an empty Status), polled via `GET /api/reconciliation/pending`.

Yandex Forms integration was removed in favour of this self-hosted form. Stage 2 (reconciliation) is implemented and now **non-destructive**; `services/drive.py` (scan archival into `dd.mm.yyyy` Drive folders) is implemented and feature-flagged off by default. `README.md` is the user-facing overview; **this file (`CLAUDE.md`) is the single source of truth for architecture and conventions** — keep AI guidance here, concrete and current, rather than spread across generated side-docs.

## Common commands

Dependencies and environment are managed with **uv** (Python 3.12). Do not use pip directly.

```bash
uv sync                                                # install deps from uv.lock
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 # run locally; open http://localhost:8000/
uv run pytest                                          # full test suite
uv run pytest tests/unit/test_vision.py                # one file
uv run pytest tests/unit/test_vision.py::test_name     # one test
uv run pytest -k pattern                               # filter by name
```

Required env vars: `ANTHROPIC_API_KEY`, `SHEET_ID`, `GOOGLE_CREDENTIALS_JSON` (Service Account JSON as a single line). Optional vars live in `app/config.py` / `.env.example`. Tests auto-set dummy values via `tests/conftest.py`.

Docker / Railway: `Dockerfile` is multi-stage (uv builder → slim runtime, non-root). Railway uses `railway.toml` with healthcheck on `/health`; the container binds `0.0.0.0:$PORT`.

## Architecture

Strict **layered architecture** with enforced downward-only dependencies; violations are treated as bugs. The shape is a thin linear ETL (handler → pipeline → service → SDK) for a single-counterparty, low-volume workload (one developer, < 100 UPDs/month), so the layers exist only to keep the request path obvious and the SDK boundaries swappable — nothing more abstract is justified.

```
api/         → pipelines/ → services/ → external SDKs
                              ↓
                            core/ (logging, errors) — stdlib + structlog only
models, config cross all layers unchanged
static/      → served via fastapi.staticfiles.StaticFiles (no templating)
```

**Request flow (`POST /api/upload`):**

1. `app/api/upd_upload.py` — thin handler. Validates `foreman: Foreman` (Literal) and `file: UploadFile` (content type whitelist + size cap). No auth — the form is public. Generates a `correlation_id`, awaits the pipeline synchronously, returns `UploadResult` as JSON.
2. `app/pipelines/upd_upload.py::process_upd` — orchestrates `files.to_png` → `vision.extract` → (when all fields present) `drive.upload` (when `settings.drive_enabled`) → `sheets.append_row(..., file_url=link)`. The Drive step uploads the **original** `raw` bytes (not the PNG) and is a **soft** failure: a `DriveUploadError` is caught, the row is still appended without a link, and the result carries `warning="drive_upload_failed"`. Catches `UnsupportedFileTypeError` / `VisionExtractionError` / `SheetsAppendError` / `AppError` and returns `UploadResult(ok=False, error=<machine_code>)` instead of raising.
3. `app/services/files.py` — only place that imports `httpx` and `pymupdf`. `to_png(data, filename, media_type)` rasterises PDF page 1 at configurable DPI; passthrough for `image/*`. The legacy `download(url)` method is kept (no callers in Stage 1) for future use.
4. `app/services/vision.py` — only place that imports `anthropic`. Calls Claude with `tool_choice` forced to the `record_upd` tool (schema defined inline; semantics in `.claude/skills/upd-vision-extraction/SKILL.md`). Retries `APIConnectionError`/`RateLimitError` with `1s/2s/4s` backoff; other SDK errors raise `VisionExtractionError` immediately. Claude emits the sentinel `<UNKNOWN>` for unreadable fields — `UPDRecord._sanitize_unknowns` in `app/models.py` converts sentinels to `None` and parses Russian-formatted amounts (`"12 345,67"` → `12345.67`). `record.needs_review` is `True` whenever any required field is `None`; in that case the pipeline does NOT write to Sheets and the form shows a warning banner.
5. `app/services/sheets.py` — only place that imports `gspread` and `google.oauth2`. Column layout is fixed in `COLUMNS` (13 columns: yellow A–D from 1С, green E–K from foreman uploads, Status L, «Файл» M = green-side Drive link). **Status stays at L** for backward-compat with the bookkeeper's existing manual statuses; the file link is appended at M. `append_row(record, ..., file_url=None)` writes a green-only row (yellow + status empty, M = link or empty); `read_all_records` reads green-block data + status + file link and skips any row whose green `№ УПД` (column E) is empty; `read_onec_records` reads yellow-block (1С) data and skips any row whose yellow `№ УПД` (column D) is empty — used both to carry register rows forward and to locate existing NO placeholders; `annotate_reconciliation(plan)` applies a `ReconciliationPlan` **non-destructively** — `batch_update` for in-place patches (A:D yellow + L status by `source_row`), `update` at the first free row for appended `NO` rows, `delete_rows` (bottom-up) for stale placeholders, then a repaint of yellow/green backgrounds + number formats over the data block (idempotent; values untouched). It **never** calls `batch_clear`. All methods are async wrappers over `asyncio.to_thread`. SDK errors are translated into `SheetsAppendError` (writes/deletes/format) or `SheetsReadError` (reads).
6. `app/services/drive.py` — only place that imports `googleapiclient` (`google-api-python-client`). `upload(data, filename, media_type, uploaded_on) -> webViewLink` find-or-creates a `dd.mm.yyyy` subfolder under `drive_folder_id` (cached per day) and uploads the original scan. **Auth is OAuth *user*, NOT the service account** (`google.oauth2.credentials.Credentials` built from `drive_oauth_client_id` / `_secret` / `_refresh_token`, scope full `drive`): a service account has no Drive storage quota, so any file it creates is rejected with `storageQuotaExceeded` (confirmed 2026-06-05 — sharing a My Drive folder with the SA does not help, the new file is owned by the SA). Uploading as a real user puts files on that user's quota. Full `drive` scope is needed to write into the user's pre-existing `drive_folder_id` (`drive.file` only sees app-created files). The refresh token comes from `scripts/drive_authorize.py` (one-time `InstalledAppFlow` consent). SDK `HttpError`s are translated into `DriveUploadError`.

**Request flow (`POST /api/reconciliation`):**

1. `app/api/reconciliation.py` — thin handler. Validates `file: UploadFile` by extension whitelist (`.xls` / `.xlsx` / `.csv`) and content-type (with size + empty checks). Generates a `correlation_id`, awaits the pipeline synchronously, returns `ReconciliationResult` as JSON.
2. `app/pipelines/reconciliation.py::reconcile` — orchestrates `onec.parse(raw, filename)` → `sheets.read_all_records()` → `sheets.read_onec_records()` → `_combine_onec(...)` → `_build_plan(...)` → `sheets.annotate_reconciliation(plan)` → `ReconciliationStats`. `_combine_onec` merges the freshly parsed register with the 1С rows already in the sheet so register entries **accumulate** across reconciliations: a new record wins on a `_normalize`d number clash (the export is authoritative — amounts may have been corrected), and any old register row absent from the new export is carried forward unchanged. `_build_plan` produces a `ReconciliationPlan` (`annotations` = in-place patches by `source_row`; `appended_rows` = new `NO` rows; `deleted_rows` = stale placeholders; `last_data_row`) plus four counts (matched / missing / extras / amount_mismatch). The green foreman rows are the append-only backbone: each is annotated in place with the matching 1С block + a status — `OK` when the amount agrees within `_AMOUNT_TOLERANCE` (0.01), `СУММА?` when the number matches but amounts diverge (foreman duplicates stay as separate annotated rows). Unmatched 1С records become `NO` (refreshed in place if a yellow-only placeholder already exists for that number, else appended below); a placeholder a later upload now matches is added to `deleted_rows`. **Status protection (variant B):** computed statuses are written via `_resolve_status` with the `·авто` marker (`_auto`), but a green row whose current status is non-empty and **lacks** the marker is treated as manual — `_resolve_status` returns `None` so the service leaves that Status cell untouched. Catches `OneCParseError` / `SheetsReadError` / `SheetsAppendError` / `AppError` and returns `ReconciliationResult(ok=False, error=<machine_code>)`. Comparison key is `_normalize(upd_number)`: lowercase, strip, drop spaces, drop leading zeros — **matching is on the number only; the amount is compared but never part of the key**. The 1С column used is `Номер вх.` (incoming UPD number from supplier) — *not* the internal 1С document number. `pending_uploads(...)` reuses `read_all_records()` to count green rows with an empty Status (uploads not yet reconciled).
3. `app/services/onec.py` — only place that imports `xlrd`, `openpyxl` and stdlib `csv`. `parse(data, filename)` branches on extension; auto-detects the header row by scanning for the «Дата / Номер / Сумма» trio; maps columns by exact name (`Номер вх.`, `Дата вх.` → fallback `Дата`, `Сумма`, `Информация`). Stops on «Итого» / signature block / blank rows. SDK errors translated into `OneCParseError`.

**Frontend:** a single `app/static/index.html` (inline CSS + JS, no bundler, no Jinja) with two tabs: «Загрузка УПД» and «Сводка». `app/main.py` mounts `StaticFiles(directory="app/static", html=True)` at `/` AFTER `include_router(...)`, so `/api/upload`, `/api/reconciliation` and `/health` win the dispatch and `/` serves the form. The upload tab POSTs `multipart/form-data` to `/api/upload` and renders one of three banners (success / needs_review / error). The reconciliation tab POSTs to `/api/reconciliation` and renders just a result banner + three numeric stat cards (Совпало / Не хватает / Лишние); the actual diff lives in the Google Sheet itself.

**Reconciliation feature flag (`reconciliation_enabled`, default `True`).** Reconciliation is now **non-destructive** (annotate-in-place + manual-status protection) and **enabled by default**. This is the **single source of truth** — there is no separate frontend constant: the page fetches `GET /api/config` on load and reveals the «Сводка» tab only when `reconciliation_enabled` is true. When set to `False` (env `RECONCILIATION_ENABLED=false`), `POST /api/reconciliation` short-circuits to `error="reconciliation_disabled"` **before** any sheet access, `/api/reconciliation/pending` returns `0`, and `/api/config` reports `false` so the tab stays hidden — all from one flag, so the tab and the endpoint can't drift out of sync. (It was paused at the client's request while the destructive rewrite was being replaced; that rework is done.)

**DI and singletons (`app/deps.py`):** `AsyncAnthropic`, `httpx.AsyncClient`, `SheetsService`, and `DriveService` are `@lru_cache` singletons; the first two are warmed in the FastAPI lifespan. `FilesService` and `VisionService` are constructed per-request via `Depends`. Tests override the service factories (`get_files_service` / `get_vision_service` / `get_sheets_service` / `get_drive_service` / `get_onec_parser_service`) via `app.dependency_overrides`.

**Settings (`app/config.py`):** All env access goes through `Settings` (pydantic-settings, `.env` loading). `get_settings()` is `@lru_cache`d — tests clear that cache between cases via the autouse fixture in `tests/conftest.py`. Feature flags `reconciliation_enabled` and `drive_enabled` (both default `False`), plus `drive_folder_id`, gate the paused/optional slices. `sheet_url` is a `cached_property` derived from `sheet_id`. `redact_settings()` masks `anthropic_api_key` and `google_credentials_json` before logging at startup.

**Logging (`app/core/logging.py`):** `structlog` with JSON (prod) or pretty (dev) renderer, driven by `LOG_FORMAT`. A `correlation_id` contextvar (`bind_correlation_id`) threads through the pipeline and is returned in the upload response so one submission can be grepped end-to-end.

## Key conventions (read before editing)

- **SDK boundaries are the only abstraction.** A `services/*` module is the **only** place allowed to import `anthropic`, `httpx`, `pymupdf`, `gspread`, `google.oauth2`, `googleapiclient` (Drive, in `services/drive.py`), `xlrd`, `openpyxl` (and stdlib `csv` is treated the same way for symmetry — it lives only in `services/onec.py`). Pipelines never import external SDKs. Handlers never call services directly — always through a pipeline.
- **Translate SDK exceptions at the service boundary** into `app/core/errors.py` types (`UnsupportedFileTypeError`, `VisionExtractionError`, `SheetsAppendError`, `SheetsReadError`, `OneCParseError`, `DriveUploadError`, base `AppError`, plus the legacy `FileDownloadError`). Pipelines handle one taxonomy. `DriveUploadError` is handled **softly** in the upload pipeline (row still written).
- **Pydantic at every edge.** `Foreman` literal + `UploadFile` for inbound, `UPDRecord` for vision output, `DownloadedFile` for files, `UploadResult` (with optional `warning`) for outbound. Stage 2 adds `OneCRecord`, `SheetUPDRow` (incl. `file_url`), `ReconRow` (incl. `green_file_url`), `RowAnnotation`, `ReconciliationPlan`, `ReconciliationStats`, `ReconciliationResult`. Inside the app, pass validated instances, never dicts.
- **Synchronous handlers.** Both `process_upd` and `reconcile` are awaited inline so the form can show the result on submit. There are no `BackgroundTasks`. If processing exceeds the proxy timeout, surface that as a backend issue — don't move work back to the background without revisiting the UX.
- **Vision extraction rules live in `app/services/vision.py::SYSTEM`** and `.claude/skills/upd-vision-extraction/SKILL.md`. When changing the tool schema or the sentinel behaviour, update **both** — `UPDRecord._sanitize_unknowns` in `app/models.py` depends on the sentinel contract.
- **1С comparison key.** The reconciliation diff matches on `_normalize(upd_number)` (lowercase / strip / no spaces / no leading zeros). The 1С source column is `Номер вх.` — never use the internal `Номер` column. If you ever need fuzzy matching or `(organization, number)` keys, that's a separate iteration; today the workflow is single-counterparty.
- **No database, no Clean Architecture.** Stated preference: minimal abstractions, modern Python tooling. Don't add repository patterns, ABCs, or "domain services" around already thin SDKs. Concretely, avoid these anti-patterns: SDK/HTTP logic in `pipelines/*` (services integrate, pipelines orchestrate); a handler reaching `services/*` directly (skips the pipeline — if the urge appears, the pipeline is too thick, so move logic, don't skip it); interfaces/protocols added "just in case" (`SheetsService` needs no `SheetsRepository` ABC — pass the concrete class and override it in tests); scattered `os.getenv` calls (all env access goes through `app/config.py::Settings`); SDK exceptions leaking past `services/*`; and adding a database (the Google Sheet is the system of record).
- **Status protection (variant B).** Reconciliation tags computed statuses with the `·авто` marker (`OK·авто` / `NO·авто` / `СУММА?·авто` / `ЛИШНЕЕ·авто`). The marker is the contract that distinguishes auto from manual: `_resolve_status` / `_is_auto` / `_auto` in `app/pipelines/reconciliation.py` own it. A status without the marker is the bookkeeper's hand-set value and is **never** overwritten. If you change the marker string, the in-place annotation will start overwriting old auto-statuses as if manual — change it deliberately and note the migration.
- **Non-destructive annotate.** `annotate_reconciliation` must never `batch_clear` the data area or rewrite the green block (E:K) / file link (M). Green rows are the append-only backbone, keyed to plan annotations by `source_row`. New `NO` rows go below via `update` at `last_data_row+1`; stale placeholders are removed via `delete_rows` (bottom-up). If you need to "rebuild", you're back to the destructive behaviour the client rejected — don't.
- **Stage 2 status.** Reconciliation (`app/api/reconciliation.py`, `app/pipelines/reconciliation.py`, `app/services/onec.py`) is implemented, non-destructive, and **enabled by default** (`reconciliation_enabled`, the single flag driving both the tab via `/api/config` and the endpoint) — see "Reconciliation feature flag" above. The pending rework is multi-organisation matching (today's diff is single-counterparty: key is `_normalize(upd_number)` only). `app/services/drive.py` (scan archival into `dd.mm.yyyy` Drive folders) is implemented and **feature-flagged off** via `drive_enabled` — turning it on needs a user `drive_folder_id` + an OAuth refresh token (`scripts/drive_authorize.py`), because a service account can't create Drive files (no quota). Do **not** revert Drive to service-account auth — it was tried and fails with `storageQuotaExceeded`.

## Tests

`pytest-asyncio` in `auto` mode; `respx` mocks `httpx` in unit tests; integration tests call the FastAPI app through `httpx.ASGITransport` with dependency overrides on `get_files_service` / `get_vision_service` / `get_sheets_service` / `get_drive_service` / `get_onec_parser_service`. Real UPD screenshots in `tests/fixtures/upd/` act as regression samples for vision — tests reading them expect to be able to stub out the Anthropic client, not hit the real API. `tests/fixtures/onec/sample.xls` is a real 1С export used as a regression sample by `tests/unit/test_onec.py`. `tests/unit/test_sheets.py` patches `gspread.authorize` and `Credentials.from_service_account_info` so SheetsService never hits Google; `tests/unit/test_drive.py` patches `drive.build` + `Credentials.from_service_account_info` so DriveService never hits Google. The reconciliation tests assert against the `ReconciliationPlan` handed to `annotate_reconciliation` (annotations / appended_rows / deleted_rows), and cover manual-status survival + placeholder deletion (NO→OK).
